15.1 報告的用途

  • 向客戶證明「達標」。
  • 向自己「可再現、可追蹤」。
  • 向量產「可驗收」。

15.2 報告結構

IQ 驗證報告範本
1. 測試條件（光源/圖卡/設備）
2. 樣本資訊（感測器/鏡頭/ISP/版本）
3. 各維度結果（曝光/色彩/雜訊/解析度/均勻度/DR）
4. 一致性（unit-to-unit）
5. 標準對照（ISO/EMVA）
6. 結論與簽核

15.3 規格書（SPEC）

  • 明列「參數 → 量測方法 → 目標值 → 門檻」。
  • 例：ΔE avg<3、MTF50 ≥0.5、暗角比 ≥0.9。

15.4 驗收流程

  1. 自測（自家報告）。
  2. 客戶測（依相同 SPEC）。
  3. 差異協調（量測條件須一致）。

15.5 練習

  1. 用範本寫一份驗證報告。
  2. 定義一份簡單規格書。

15.6 深入：報告的「可重現性」承諾

一份合格的 IQ 報告，別人照條件重測應得相近數字。因此：量測條件、工具版本、EMVA 版本、樣本 ID 都要寫清。

15.7 深入：規格書的「可驗收」寫法

SPEC 範例條目
項目: 色彩保真度
量測: 24 色卡, D65, 固定曝光
目標: ΔE00 avg < 3, max < 6
方法: CIE DE2000（標明版本）
判定: 全色塊合格

15.8 Worked Example：SPEC 條目撰寫

範例
項目: 低光雜訊
量測: 5 lux, 灰卡, 固定曝光
指標: SNR（EMVA 定義）
目標: ≥ 20 dB
方法: 灰框 σ + 均值
判定: 全測點合格

動手：為你系統寫 3 條 SPEC。

EMVA 1288 對應：報告中的 EMVA 章節

EMVA 1288 是感測器層的標準量測（QE、飽和、雜訊、動態範圍）。它定義了「感測器送出 RAW 的品質天花板」——以下與本單元對應的規範、公式與調校方向。

EMVA 1288 參數公式/定義本單元驗證
報告格式EMVA 1288 報告範本（參數表+曲線）一致性報告
數值很差時怎麼調（客戶質疑感測器規格）：
  • 現象：客戶要 EMVA 原始量測而非廠商 datasheet。
  • 調校方向：依 EMVA 1288 標準流程自測並附量測條件——報告要能重現。

本單元 EMVA 報告門檻

項目規範
EMVA 版本標明 1.0/2.x，量測條件一致
參數表η/飽和/σ_d/PRNU/DSNU/SNR/DR 全列
可重現附溫控、光源、曝光條件

15.9 補強：報告要能被第三方重建

結論頁之外，附件至少要有量測 log、原始 RAW/影像索引、分析腳本或工具版本、圖卡與光源資訊、EMVA 1288 版本、樣本序號與參數差異。每個 PASS/FAIL 都要連到一筆原始資料；若數值與典型門檻不同，說明是產品 SPEC、方法差異或量測不確定度。

一條合格報告紀錄
MTF50 | ISO 12233 slanted edge | center | 0.52 c/p

15.10 補強練習：寫出可驗收 SPEC


  1. 為 SNR/DR、MTF50、ΔE、暗角比各寫一條完整 SPEC。
  2. 每條包含方法標準、設備條件、單位、樣本數、門檻、允許例外與證據位置。
  3. 請另一位讀者只依 SPEC 重測，記錄雙方差異並修正文句。

進階真實情境 Worked Example：可重現報告的附件完整性


進階範例：報告附件完整性檢查
場景：客戶退貨報告，理由「無法重現量測結果」。

附件清單檢查：
□ 量測 log（光源/圖卡/距離/曝光/增益/AWB）
□ 原始 RAW 檔索引（檔名→指標對照表）
□ 分析工具版本（Imatest 6.x / Python 3.x）
□ 圖卡版本與方向標記
□ EMVA 1288 版本與溫控記錄
□ 樣本序號與感測器批次
□ 每項 PASS/FAIL 連到一筆原始資料

缺失：未附光源校準日期 → 客戶無法確認
光源是否漂移 → 報告無效

為什麼這條路徑：
報告不只是結論 → 附件是「可重現性的證據」→
缺附件 = 報告不可信。


動手：為你的報告做一次附件完整性檢查。


為什麼選這條調校路徑：報告的附件不是配角——量測 log、原始 RAW 索引、工具版本、光源校準記錄都是「可重現性的證據」，缺了任何一項報告都不可信。



進階原理：報告的法律效力與可追溯性


在醫療/車載/航空等領域，IQ 報告具有法律效力。報告必須包含：量測人員簽章、設備校準證書編號、原始資料保存期限、異議處理流程。缺少任一項，報告在法律上可能無效。


陷阱案例：「報告 PASS 但未附設備校準證書 → 客戶法律團隊退回」——技術上正確但法律上不完整。



診斷式疑難排解





症狀可能原因解決方案


報告被客戶退回缺少量測 log 或設備校準記錄補充完整附件 + 建立附件清單


報告中 PASS 但客戶重測 FAIL量測條件不一致在報告中明確記所有量測條件


報告無法追溯到原始資料未建立檔名→指標對照表自動生成索引表


SPEC 寫法模糊無法驗收未定義量測方法與判定標準每條 SPEC 附方法、單位、門檻


報告簽核流程不完整缺少法律效力要件補充簽章、校準證書、保存期限





進階挑戰題

    2. 

  2. 設計一個「SPEC 審查流程」：如何確保每條 SPEC 都包含方法、單位、門檻、判定標準、允許例外。請另一位工程師只依你的 SPEC 重測，記錄差異。
    3. 

  3. 建立一個「報告品質檢查表」：包含附件完整性、可追溯性、簽核流程、法律效力要件等 15+ 條檢查項。
