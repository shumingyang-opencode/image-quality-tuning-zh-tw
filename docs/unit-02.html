2.1 為什麼術語重要

IQ 調校是跨領域：感測器工程、光學、信號處理、色彩科學。術語是「溝通的錨點」。本單元按維度分類講解核心術語；完整清單見術語表。

  2. 用 glossary.html 查 3 個你不熟的術語。

2.8 深入：術語的「單位陷阱」

術語單位陷阱
SNRdB vs 線性比（20·log10 與 10·log10 差異）
MTF50cycles/pixel vs LP/mm vs LW/PH
增益倍數 vs dB vs ISO
雜訊e⁻ vs LSB vs 灰階
溝通災難：報數字不帶單位/定義 = 無意義。規格書務必標明「量什麼、怎麼量、單位」。

2.9 深入：術語與 EMVA 1288 的對應

多數「雜訊/動態範圍」術語，在 EMVA 1288 都有精確定義（σ_d、η、μ_p.sat…）。讀懂 EMVA 的定義，才能避免各說各話。

2.10 Worked Example：把術語翻譯成量測

範例
術語      → 定義                    → 量什麼
SNR       → 訊號/雜訊比             → 灰框 σ + 均值
動態範圍  → 飽和/雜訊底             → EMVA DR
LSC       → 四周亮度不均            → 積分球暗角比
Moiré     → 取樣混疊假影            → 細網格圖卡

動手：抽 5 個術語，寫出「定義 → 量什麼 → 用哪張圖卡」。

2.11 補強：同一個詞要綁定測量定義

「雜訊」若不說是 temporal、spatial、RAW 還是輸出影像，數字就不能比較；「MTF50」若不說是中心或角落、cycles/pixel 或 LW/PH，也不能作為 SPEC。EMVA 1288 偏重感測器物理量，ISO 12233/15739 偏重相機與圖卡結果，報告應同時寫明層級。

術語轉成驗收句
術語：SNR

2.12 補強練習：抓出含糊規格


  1. 找一條只寫「畫質好」或「低噪」的需求，改寫成指標、圖卡、光源、單位與門檻。
  2. 對 MTF、DR、ΔE 各寫一條「不符合定義就不能比較」的提醒。

進階真實情境 Worked Example：跨標準術語翻譯實戰


進階範例：客戶規格書術語翻譯
客戶需求原文：
  "Low-light SNR > 30dB, resolution > 2000 LW/PH"

翻譯步驟：
1. SNR 30dB → 定義：灰框均值/σ（dB），光源 D65, 10lux
2. 2000 LW/PH → 轉換為 cycles/pixel：
   LW/PH ÷ (2 × pixels_per_line)
   假設 1920pixels → 2000/(2×1920) ≈ 0.52 c/p
3. 方法標準：SNR → ISO 15739；LW/PH → ISO 12233
4. 補充：標明色溫、曝光、ROI、單位

為什麼這條路徑：
客戶說的是「結果語言」，工程需要「量測語言」→
翻譯是避免規格歧義的第一步。


動手：找一條含糊的規格需求，做一次完整的術語翻譯。


為什麼選這條調校路徑：規格書上的「結果語言」必須翻譯成有明確定義、單位、量測方法的「工程語言」，才能避免驗收時各說各話。



進階原理：感測器光譜響應與色域映射


感測器的 R/G/B 通道有各自的光譜響應曲線 S_R(λ), S_G(λ), S_B(λ)。CCM 本質上是把「感測器色域」映射到「目標色域」（如 sRGB）的線性變換。數學上：


CCM 映射
[R_out]       [R_sensor]
[G_out] = CCM × [G_sensor]
[B_out]       [B_sensor]

CCM 是 3×3 矩陣，由最小二乘法求解：
min Σ ||target_color − CCM × sensor_color||²


陷阱案例：「CCM 對角線越大越飽和」——但若感測器色域與目標色域重疊小，強行拉大對角線會造成色域外裁切（gamut clipping），某些飽和色反而失真。



診斷式疑難排解





症狀可能原因解決方案


規格書寫「SNR 好」但無法驗證未定義 SNR 的量測方法與單位補充：定義 ROI、光源、公式、單位


兩邊報告數字差 3dBSNR 用 10·log10 vs 20·log10統一用 20·log10（振幅比）
