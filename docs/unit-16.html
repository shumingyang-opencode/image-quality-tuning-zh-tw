16.1 完整工作流

量測基準→校正→美化→驗證→一致性→報告

16.2 校正順序（不可跳）

  1. 黑位（統計地基）。
  2. LSC（均勻度）。
  3. AWB/CCM（色彩）。
  4. 曝光基準（AE）。

16.3 美化順序

  1. NR ↔ Sharpen（成對）。
  2. Tone/HDR。
  3. 色彩喜好微調。

16.4 驗收清單

checklist
□ 曝光誤差 < 5%
□ ΔE avg < 3
□ MTF50 ≥ 規格
□ 暗角比 ≥ 0.9
□ SNR 依規格
□ unit-to-unit 在規格內
□ 報告輸出

16.5 總複習

  1. 把 16 單元串成你的 SOP。
  2. 建立「量測→調校→驗證→報告」模板。

16.6 深入：調校的「回歸守則」

  • 每次改動跑「快照場景」回歸（色彩/雜訊/解析度）。
  • 用 EMVA 參數當「根因檢查」：調不上去先看感測器。
  • 參數進 git，附 log 與前後圖。

16.7 深入：從「會調」到「會驗收」

真正的能力不是「把這顆調好看」，而是「建立一套可重現、可比較、可驗收的流程」——把本課的 16 單元串成你的 SOP。

16.8 Worked Example：一顆感測器的完整流程

流程
1. EMVA：η/σ_d/DR（感測器確認）
2. 黑位校正 → 3. LSC → 4. AWB/CCM
5. AE 基準 → 6. NR ↔ Sharpen
7. 驗證：SNR/ΔE/MTF/暗角比 全過
8. unit-to-unit：5 台抽查
9. 出報告 + SPEC 對照

動手：照此 SOP 走完你手上的一顆感測器。

EMVA 1288 對應：工作流中的 EMVA 位置

EMVA 1288 是感測器層的標準量測（QE、飽和、雜訊、動態範圍）。它定義了「感測器送出 RAW 的品質天花板」——以下與本單元對應的規範、公式與調校方向。

EMVA 1288 參數公式/定義本單元驗證
先 EMVA 後 ISP先測感測器（EMVA），再調 ISP根因導向
數值很差時怎麼調（「調不上去」）：
  • 現象：tuning 撞牆通常是感測器達不到。
  • 調校方向：回 EMVA 1288：確認 η/飽和/雜訊是否符合預期；感測器上限確定後，才知道該補光、換感測器、還是只能接受。

本單元 EMVA 門檻總結

出貨門檻檢查
η ≥ 40% · σ_d < 5 e⁻ · DR ≥ 60 dB
SNR(中灰) ≥ 30 dB · PRNU < 2% · 壞點 < 0.1%

16.9 練習：完成一輪可交付工作流

  1. 先固定 D65、溫度、鏡頭、FW 與圖卡，取得 EMVA 1288 暗框/亮框基線。
  2. 依序跑黑位、LSC、AWB/CCM、AE，再調 NR/Sharpen 與 tone；每次只改一組參數。
  3. 用 ISO 12233 SFR/MTF、ISO 15739 雜訊、ISO 14524 OECF 及色卡驗證輸出。
  4. 以 5 台以上做 unit-to-unit，將 SNR、DR、MTF50、ΔE、暗角比與離群值寫入報告。
完成條件
□ 每一項 PASS 都有 raw、圖、公式、單位與條件

16.10 補強：停止條件與回退策略


當 NR 提升 SNR 卻使 MTF 下降、CCM 降低平均 ΔE 卻放大單色誤差、或 tone 保留暗部卻造成高光 clipping，應回到 SPEC 的優先序，不要無限調參。保留每個候選版本與回歸結果；若 sensor 的 η、滿阱或暗雜訊已是瓶頸，將問題升級到硬體/光學，而不是繼續堆 ISP。

進階真實情境 Worked Example：完整調校→驗收→回退策略


進階範例：完整調校含回退策略
場景：新專案 IQ 調校，但感測器 η 只有 35%（偏低）。

完整工作流含回退：
1. EMVA：η=35%（低於 40% 門檻）→ 標記風險
2. 黑位 → LSC → AWB/CCM（正常流程）
3. NR 開強 → SNR 達標但 MTF 掉 15%
4. 回退：NR 降至中等 → SNR 略低但 MTF 保留
5. 決策：接受「SNR=28dB + MTF=0.45」的組合
6. 記錄：感測器 η 偏低 → 限制了 NR 的取捨空間

為什麼這條路徑：
調校不是「一直往前」→ 遇到瓶頸要能回退 →
記錄決策過程比最終數字更重要。


動手：在你的調校中加入「回退策略」記錄。


為什麼選這條調校路徑：調校不是一直往前衝——遇到感測器瓶頸時要能回退、記錄決策過程，最終的取捨理由比數字本身更有價值。



進階原理：調校的「技術債」概念


軟體有技術債，IQ 調校也有：「現在勉強過關但未來會造成問題」的參數設定。例如：NR 開太強暫時掩蓋雜訊問題，但換感測器後 MTF 會崩潰。好的調校應該「最小化技術債」。


陷阱案例：「NR=10/10 暫時 SNR 達標 → 換感測器後 MTF50 從 0.5 掉到 0.2」——因為 NR 依賴高 SNR 輸入，新感測器 SNR 不同 → NR 過強反而傷畫質。



診斷式疑難排解





症狀可能原因解決方案


調校到某一步卡住無法前進感測器已達物理上限回 EMVA 確認 → 若感測器極限則接受或換硬體


每次改參數都要重跑全部驗證未建立「快照回歸」集建立核心場景快照集，每次只跑受影響指標


參數改了但不知道改了什麼未做版本控制參數進 Git + 附 log 與前後圖


換人接手完全無法理解缺少調校決策記錄記錄每次調校的「為什麼」而不只是「改了什麼」


量產後發現問題但找不到原因調校過程未保留歷史版本保留每個候選版本與回歸結果

  2. 設計一個「調校技術債評估」流程：如何判斷目前的參數設定是「長期可行」還是「暫時掩蓋問題」？建立評估標準。
